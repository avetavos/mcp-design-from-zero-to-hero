## อีกครึ่งหนึ่งของ protocol

ที่ผ่านมาคอร์สนี้มอง MCP จากฝั่ง server เป็นหลัก: จะเปิด tool, resource และ prompt ออกมาอย่างไร โมดูลนี้จะพลิกมุมมอง ถ้าคุณกำลังสร้าง AI application ไม่ว่าจะเป็นผู้ช่วยใน IDE, ผลิตภัณฑ์แชท หรือ agent ที่ทำงานเอง แปลว่าคุณกำลังสร้าง **host** และภายใน host นั้นคุณจะสร้าง **client** หนึ่งตัวต่อหนึ่ง server ที่เชื่อมต่อ

ความต่างนี้สำคัญ เพราะ protocol กำหนดหน้าที่ให้ทั้งสองต่างกัน:

- **client** คือ object ระดับ protocol มันคุย JSON-RPC กับ server เพียงตัวเดียวผ่าน transport เดียว ส่ง `_meta` ไปกับทุก request และแปลงผลลัพธ์บน wire ให้เป็นค่าที่มี type
- **host** คือตัว application มันเป็นเจ้าของ language model, บทสนทนา, user interface, การตัดสินใจเรื่อง consent และ registry ที่รวม tool จากหลาย client เข้าเป็น list เดียวที่ model มองเห็น

## ทำไมต้องมี client หนึ่งตัวต่อหนึ่ง server

MCP เป็น protocol แบบ stateless: ทุก request พก protocol version, client capability และตัวตนของ client ไปด้วย แต่ก็ยังมีเหตุผลดี ๆ ที่ควรเก็บ client object ไว้หนึ่งตัวต่อหนึ่ง server เพราะแต่ละ server มี transport ของตัวเอง (subprocess หรือ HTTP origin), มี capability ที่ discover มาได้ต่างกัน, มี credential ของตัวเอง และมีชื่อ tool ของตัวเอง ถ้าเอาหลาย server ไปซ่อนไว้หลัง client ตัวเดียว host จะต้องคอยแยกแยะทั้งหมดนั้นทุกครั้งที่เรียก การแยกไว้ทำให้ host มอง server เป็นหน่วยหนึ่งที่ connect, disconnect และ revoke ได้อย่างอิสระ

host คือจุดที่การรวมเกิดขึ้น มันขอ `tools/list` จากแต่ละ client, ใส่ prefix หรือ namespace ให้ชื่อเพื่อกันชนกัน (server สองตัวอาจเปิด `search` ทั้งคู่) แล้วส่ง list ที่รวมแล้วให้ model

## host เป็นเจ้าของอะไรบ้าง

| เรื่อง | ใคร | ทำไมถึงอยู่ตรงนั้น |
|---------|-----|--------------------|
| คุย JSON-RPC, ใส่ `_meta`, parse ผลลัพธ์ | Client | เป็นงานกลไกล้วน ๆ มีหนึ่งตัวต่อ transport |
| ตัดสินว่า tool call ไปที่ server ไหน | Host | มีแต่ host ที่เห็น server ทุกตัว |
| เรียก LLM และรัน tool loop | Host | protocol ไม่เคยคุยกับ model โดยตรง |
| ถามผู้ใช้ก่อนรัน tool ที่ทำลายข้อมูล | Host | spec บอกว่าควรมีมนุษย์ที่ปฏิเสธ call ใดก็ได้ |
| แสดง form ของ elicitation และขอ consent ก่อนเปิด URL | Host | host เป็นเจ้าของ UI |
| ถือ OAuth token และ API key | Host | credential ต้องไม่ไปถึง model หรือ sandbox เด็ดขาด |
| cache `tools/list` ตาม `ttlMs` และ refresh เมื่อได้ `list_changed` | Host | เป็น policy ที่ข้ามหลาย request |
